## 2. Pare de gerar cabeçalhos a partir de posições arbitrárias

O comportamento atual — até 22 campos identificados por posição e vários cabeçalhos genéricos — demonstra que o sistema está usando posições horizontais ou agrupamentos de texto como se cada posição fosse uma coluna real.

Corrija esse comportamento.

**A quantidade de segmentos de texto, coordenadas ou posições detectadas não é igual à quantidade de colunas da tabela.**

Uma linha pode conter:
- Um nome composto por vários segmentos de texto.
- Campos vazios que não geram segmentos.
- Valores separados por distâncias diferentes.
- Indicadores “X”.
- Uma palavra como “Convocado”.
- Fragmentos de texto que precisam ser unidos dentro do mesmo campo.

Esses casos não devem criar novas colunas.

Não gere automaticamente cabeçalhos “Campo 1”, “Campo 2” ou “Cabeçalho não identificado” para cada posição detectada. Primeiro identifique os cabeçalhos reais da tabela e depois associe os valores a eles.

Quando um cabeçalho não puder ser identificado, não o substitua por uma coluna arbitrária. Registre a incerteza e sinalize para revisão.

## 3. Use o cabeçalho real para determinar os limites das colunas

Utilize os segmentos de texto e suas coordenadas fornecidos pelo PDF.js, mas implemente uma reconstrução tabular orientada pelos cabeçalhos.

Fluxo esperado:

1. Extraia os segmentos de texto com suas coordenadas X/Y e informações de página.
2. Identifique a região da página que contém a tabela de candidatos.
3. Localize a linha dos cabeçalhos reais.
4. Identifique a posição horizontal de cada cabeçalho.
5. Estabeleça limites de coluna coerentes com a geometria da tabela, usando os cabeçalhos e os limites visuais disponíveis.
6. Agrupe os segmentos de texto das linhas seguintes em registros de candidatos.
7. Associe cada valor à coluna correspondente usando os limites identificados.
8. Trate cabeçalhos repetidos nas páginas seguintes sem criar novas colunas.
9. Valide o resultado com os tipos de dados esperados e com o documento original.

Não calcule os limites de cada linha isoladamente com base apenas nos espaços entre os valores. Isso produz uma estrutura diferente em cada linha e causa o deslocamento dos campos.

Os limites das colunas devem ser consistentes dentro da mesma tabela e podem ser recalibrados apenas quando uma mudança real de estrutura for detectada no documento.

Se o PDF tiver uma tabela visualmente organizada, utilize também as linhas divisórias ou outros elementos gráficos disponíveis para confirmar os limites, quando aplicável.

## 4. Corrija especificamente os campos que estão sendo agrupados

Os seguintes campos devem ser tratados separadamente:

- `INSCRIÇÃO` e `CLAS`.
- `MF`, `PORT`, `MAT`, `ING` e `RED`.
- `DT_NASC`, `AC`, `RV` e `CI`.
- Cada campo de status, incluindo os indicadores `X` e o texto `Convocado`, conforme os cabeçalhos reais.

Não agrupe `INSCRIÇÃO` com `CLAS` porque ambos contêm números.

Não agrupe `DT_NASC`, `AC` e `RV` porque aparecem próximos horizontalmente.

Não desloque os campos de notas ou status para preencher espaços vazios.

A atribuição deve considerar a posição horizontal em relação aos limites das colunas e a estrutura da tabela. A validação pelo formato do dado pode ajudar, mas não deve substituir a geometria do documento.

### Exemplos de validação semântica

- `INSCRIÇÃO`: identificador numérico; preserve-o como texto para não perder zeros à esquerda.
- `CLAS`: posição de classificação, distinta do número de inscrição.
- `MF`, `PORT`, `MAT`, `ING` e `RED`: valores numéricos de notas, conforme o formato original.
- `DT_NASC`: data, por exemplo `19/06/2008`.
- `AC`, `RV` e `CI`: campos independentes, conforme seus valores e significados no documento.
- `X`: indicador que deve permanecer na coluna em que aparece no documento.
- `Convocado`: situação textual, não uma nota ou uma classificação.

Não use somente expressões regulares para preencher os campos, porque isso pode colocar uma data ou um número na coluna errada quando houver valores ausentes ou formatos diferentes.

Preserve os dados brutos e permita revisão quando não houver confiança suficiente para atribuir um valor a uma coluna.
